## Context

The kernel stays small: identity, tenancy, authorization, the plugin host, brokered persistence, the outbox, and the other services in spec §3. Every feature, including first-party features, is a plugin. Plugins depend on each other through public contracts and the event log ([ADR-0003](0003-outbox-pgboss.md)), never through each other's tables (spec §4.8). A plugin owns its tables and its SQL migrations, and installing one must not require a kernel schema edit.

D06 chooses the typed query API for that kernel. The register records that β and γ independently selected Kysely over node-postgres, with Drizzle as the ergonomics fallback and Prisma 6 rejected for this project on generated-type compile cost. The register leaves the choice gated on Spike A. This record applies that gate to the versions current on 2026-10-25 and states how the chosen API meets four criteria the spec already binds:

1. **Plugin-owned schemas.** A plugin adds tables by shipping SQL. The kernel source does not change.
2. **Migration order across dependent plugins.** Replicas apply the same order. Order follows the manifest's contract dependencies. It does not authorize a cross-plugin foreign key.
3. **Tenant isolation.** Transaction-local tenant context on a PgBouncer transaction-mode pool, fail-closed when the context is missing, and recovered when a session is contaminated.
4. **Testability.** The tenancy path and the typecheck path have a rerunnable oracle. A mock of the query API is not evidence of RLS.

Plugins never hold a database connection (ADR-0001). The query API is the kernel's and the broker's. Plugin SQL is declared, admitted, and executed inside the broker's transaction (spec §4.3).

`pg` 8.23.1 `Query.requiresPreparation` uses the extended protocol when the query has values, and it sends a statement name only when one was set. With no name, the statement name is empty. That is the unnamed discipline A4 observed. Kysely 0.29.6 `PostgresDriver.beginTransaction` sends the text `begin` when isolation and access mode are unset, and `commit` / `rollback` the same way. Those texts have no parameters, so they stay simple queries, which is how PgBouncer sees the transaction end. The report records that split.

The current PgBouncer manual (retrieved 2026-10-25) still says: transaction mode releases the server connection when the transaction finishes; `max_prepared_statements` defaults to 200 and `0` disables named-statement tracking in transaction mode; `server_reset_query` defaults to `DISCARD ALL` and does not run in transaction mode unless `server_reset_query_always` is on (default 0). The measured binary is 1.26.0, as in the report and ADR-0007.

## Decision

1. **The kernel query API is Kysely 0.29.6 on node-postgres `pg` 8.23.1.** One `Kysely` instance per pool, `PostgresDialect` constructed with that `pg.Pool`. The pool is visible at the construction site. Kernel code does not call `pool.query` for any statement that belongs to a tenant transaction. node-postgres documents that `pool.query` checks out whichever client is idle.
2. **Tenant work runs inside `transaction().execute` with no isolation or access-mode override.** The published 0.29.6 driver then sends `begin`, the callback, and `commit` or `rollback` on the one connection `provideConnection` acquired. The ordered hygiene protocol (plan §2) runs at the start of that callback: inspect, terminate and discard on contamination ([ADR-0007](0007-pooled-contamination-recovery.md)), then `set_config(…, true)` (PostgreSQL 18: `is_local` true applies for the current transaction only), then read the value back, and only then touch tenant tables. The callback's transaction object is the only executor. A query on the outer `Kysely` instance is a different checkout and is a defect on this path.
3. **The default client leaves statement names empty.** Named statements stay the A4b branch: installed for that experiment, `max_prepared_statements` above 0, removed afterward. A4 already measured unnamed traffic as more expensive than named (means 30.4%, 27.3%, and 25.7% on the direct connection). That cost is accepted. Switching the default to names is a later decision and needs its own note; A4b shows the branch can pass, and this record does not take it.
4. **SQL is the schema source of truth. The ORM migrator is not the journal.** Kernel and plugin migrations are SQL files. The kernel journal applies them. Kysely's `Migrator`, `drizzle-kit`, and Prisma Migrate do not. `kysely-codegen` 0.20.0 runs in CI against the migrated kernel schema, its type-only output is committed, and a diff fails the check. The spike proved that check; it is not a required workflow yet. It becomes one when the kernel schema lands. Codegen is not in the appliance boot path.
5. **The kernel `Database` interface names kernel tables only.** Plugin schemas are excluded (`include`/`default-schema` scoped to the kernel schema). A plugin may generate types for its own package. The kernel does not import them. Domain nouns stay in the plugin that owns the table, which is what the kernel-purity gate is for.
6. **Plugins own tables by shipping SQL, under D08.** Each plugin schema holds tables, indexes, and constraints. The migration role has `CREATE` on that schema only. The boundary checker, against the live database, requires `tenant_id NOT NULL`, `ENABLE` and `FORCE ROW LEVEL SECURITY` (PostgreSQL 18: force subjects the table owner; superusers and `BYPASSRLS` still bypass), exactly one canonical permissive policy (permissive policies combine with `OR`), tenant-preserving composite foreign keys, and runtime DML grants. `GRANT ALL` stays forbidden.
7. **Journal order is the manifest graph, then filenames.** Pending kernel SQL runs first, so a plugin can declare the spec's read-only `REFERENCES` on kernel identity columns. Plugin packages then run in topological order of "requires a port this plugin provides." Ties break by plugin id, bytewise ascending, so every replica computes one order. A cycle fails admission and nothing in that graph migrates. Inside a package, filenames sort alphanumerically, the same ordering rule Kysely documents for its migrator. A statement that names another plugin's schema fails the boundary checker. Contract dependence is not a foreign key: spec §4.8 keeps cross-plugin reads on the owner's port or on the event log. Per-tenant reference migrations stay the background batches in spec §5. They are not part of this schema order and they do not run on the request path.
8. **Tests hit PostgreSQL.** The spike suite, including the raw-`pg` control, is the regression for pinning, leak-freedom, and contamination recovery. The two-tenant suite in spec §5, with the vacuity control the spike already ran (skip the context install, expect 0 rows and the guard), is the regression for plugin SQL. The A5 ceiling (band 75, 375 queries, 120 s, 4 GB decimal, TypeScript 5.9.3) is the regression for the kernel interface. A unit test that replaces the query API with an in-memory fake does not count for any of those three.

## Consequences

- Adding a plugin table is a SQL file in that plugin, a boundary-checker run, and a journal entry. It is not a kernel type change and not a kernel release by itself.
- The broker's WorkUnit is one `transaction().execute` callback: admitted plugin statements, the audit row, and the outbox row commit or roll back together. IPC waits stay outside that callback (spec §4.3).
- `set_config` on this path is the transaction-local form. Session `SET`, `LISTEN`, and session advisory locks stay off pooled connections (spec §5). Activation and migration locks use an unpooled connection, as the plan already says.
- Unnamed extended queries are re-prepared on every execution. A4 priced that against named statements on a direct connection. The pooler does not cache them while `max_prepared_statements` is 0, and the manual says that setting cannot track unnamed statements anyway.
- Moving the pin to Kysely 0.29.7, or the typecheck to TypeScript 7.0.2, is a rerun of the affected spike rows. It is not implied by this record. 0.29.7's release notes (2026-10-17) describe connection-release fixes on controlled transactions (`startTransaction`), which this decision does not use. The notes are not evidence that the callback path is unchanged.
- Kysely 0.29.6 declares `engines.node` of `>=22`. The repo `.nvmrc` is 24. The scored runs used Node v24.22.0 and, for A4b and the replay, v22.23.4.
- `kysely-codegen` 0.20.0 has its own dependencies and stays a development tool. It is not a kernel runtime dependency. The kernel runtime dependency added by this decision is `pg` 8.23.1 (MIT), which itself depends on `pg-pool`, `pg-protocol`, `pg-types`, `pg-connection-string`, `pgpass`, and `pg-cloudflare`.
- Read replicas remain incompatible with pinning a transaction to one primary connection (spec §5). This record does not change that.

## Rejected alternatives

- **Drizzle ORM 0.45.4 as the kernel client.** It can speak node-postgres and it can generate SQL, and the register keeps it as the fallback if typecheck ergonomics fail. Spike A did not fail that way, and Drizzle was not measured. Its typed surface is a runtime schema module, so plugin tables described there become application imports. That fights criterion 1 and the kernel-purity rule. Database-first `pull` still produces that module, which someone must then keep aligned with the SQL the journal actually applied.
- **Kysely's `Migrator` as the plugin journal.** It runs TypeScript `up`/`down` functions from one folder, in alphanumeric filename order, with an optional `allowUnorderedMigrations`. Plugin packages arrive as installed artifacts, their dependency edges are manifest ports, and their migrations are SQL under a role that can `CREATE` in one schema. A TypeScript migrator inside the plugin process would also give that process a database connection, which ADR-0001 forbids.
- **Prisma ORM 6** (`@prisma/client` dist-tag `prev` is 6.19.3, published 2026-04-01). The register rejects it for this project because of generated-type compile cost and codegen coordination. Spike A did not remeasure it. The fallback on an ergonomics failure is Drizzle, never Prisma (plan §3.0).
- **Prisma ORM 7.10.1 with `@prisma/adapter-pg`.** Driver adapters are required. The adapter sits on `pg`, so a pinning or pooling failure of `pg` is a failure of this stack too, and the register's rule is to redesign the tenancy substrate rather than swap ORMs. The generated client is still a project-wide artifact. It was not spiked.
- **Prisma ORM 8** (`prisma` 8.0.0-rc.27, `@prisma/orm-postgres` 8.0.0-rc.20). The release-status page, with a table dated 23 October 2026, presents it as a release candidate and says the 8.x CLI does not read `schema.prisma`. The supported-versions page gives PostgreSQL a minimum of 15 and a driver built into `@prisma/orm-postgres`, which is a different substrate from `pg` and was not measured. The transactions page says a query made on `db` inside the callback runs on its own connection. That is the wrong shape for a single `set_config` scope. It is not the D06 fallback.
- **Raw `pg` as the kernel client.** The A1 control shows it pins a transaction when the caller holds one client. It does not give a derived row type, so a schema drift is not a compile error. D06 exists for that fail-closed property. Raw `pg` stays the diagnostic control in the suite.
- **Schema-per-tenant, a generated client that unions every plugin, and session-level `SET` on the pool.** Spec §18 and D05 already reject the first. A union client puts plugin nouns in the kernel and changes the kernel whenever a plugin ships a table. Session `SET` is the leak A2 and ADR-0007 exist to close; PostgreSQL's `set_config` with `is_local` false applies for the rest of the session, and transaction-mode PgBouncer does not run `DISCARD ALL` between transactions.

## Flip conditions

- **Driver-level failure** of connection pinning, transaction-local `set_config`, or PgBouncer transaction mode, established by the plan §3.0 protocol (raw-`pg` control fails the same way, effective config recorded, at least three runs): redesign the tenancy substrate. Do not swap in Prisma. Drizzle on `pg` is the same substrate and is not a remedy for that class.
- **Typecheck failure at the A5 acceptance point** (band 75, 375 queries, above 120 s or 3906250 KiB on the CI runner class, TypeScript 5.9.3, corpus lint intact): fall back to Drizzle and rerun A1–A5 on that client before any schema work. Do not fall back to Prisma. An overrun at band 200 or 400 is a stress input, not this flip. The measured curve did not overrun.
- **Unnamed-statement discipline itself fails** (a non-empty name on the default client): driver-level, per the plan. The overhead result does not flip the client. A4b remains available and unadopted.
- **A future pooler no longer replays `search_path`.** ADR-0007's flip applies. Re-measure before removing the socket discard. The ORM choice stays.
- **Adopting Kysely 0.29.7, the 0.30.0-beta.2 `next` tag, TypeScript 7.0.2, or Prisma ORM 8.** Each one is a new measurement on the rows it can affect, written down as its own note. None of them is authorized by the registry having moved.

## Review

This file is the proposed decision. It is not a review receipt. The task is high-risk because it records the tenancy path. Acceptance needs a receipt on the accepting revision: reviewed SHA, reviewer role, accountable sponsor, verification summary, outcome, opaque evidence ID, and a family-separation assertion.
